# Run on the H200 server

## 1. Separate the GPU server from the agent client

Install the agent project as described in the root README. Use a different
virtual environment or the official vLLM container for model serving; do not
mix the vLLM/PyTorch dependencies into the locked agent environment.

Choose an open-weight checkpoint that supports vision, tool calling and JSON
schema output. A text-only model can run Research but cannot replace Observation.
A model name, tool parser, quantization and GPU memory fit cannot be inferred
from the H200 name alone. No model weights are bundled or downloaded here.

In a serving environment with vLLM installed:

```bash
export MODEL_PATH=/path/to/your/local-vlm-checkpoint
export TOOL_CALL_PARSER=the_parser_supported_by_your_model
export TENSOR_PARALLEL_SIZE=1
export MAX_MODEL_LEN=65536
# Optional: export LOCAL_MODEL_API_KEY=your_local_server_key
bash scripts/serve_model.sh
```

The script binds to loopback and names the model `local-vlm`. Change the model
or parser using the selected checkpoint's official serving instructions. Append
model-specific flags such as a chat template, reasoning parser, quantization or
multimodal limits to the script command. The tool parser must support strict
schemas and auto/required/none choices; not every parser does. Existing wells
can contain many images, so test image-count and context limits explicitly.
Start with one well before raising concurrency.

If the client is on another machine, use an SSH tunnel to the loopback service:

```bash
ssh -L 8000:127.0.0.1:8000 user@your-h200-host
```

## 2. Check the model capabilities

Edit `configs/local.example.json` or copy it to your own config. The model ID
must match `/v1/models`; `base_url` ends in `/v1`. Export `LOCAL_MODEL_API_KEY` in
the agent environment if the server requires authentication. Without it, the
client sends the placeholder `not-required`, never an OpenAI credential.

```bash
python -m realclip_d.local_provider_check --config configs/local.example.json \
  --output runs/check-count
python -m realclip_d.local_provider_check --config configs/local.example.json \
  --output runs/check-vision-tool --generate
```

The first command checks the served model and `/tokenize` with a synthetic image
and tool definition. The second opts into two local inference turns: the initial
image is red; a tool returns a blue tile; the model must name the returned tile's
color using structured output. This checks basic image input, tool execution,
tool-image follow-up and JSON schema output. It does not validate cell biology.
A missing/unsupported tokenizer endpoint or omitted usage fails explicitly.

The adapter counts the same SDK-converted messages and tools used for generation,
including images. A proxy must route both `/v1/*` and `/tokenize` to the same
model server and protect them consistently. Server/tokenizer implementations
must count expanded multimodal tokens; confirm this for the chosen deployment.
No approximate image-byte token fallback is used.

## 3. Prepare actual input files

Use `examples/sample.json` as a schema example only. Its compound, images and CP
values are synthetic; do not send that fictional identity to live databases.

A research-only input needs `sample_id`, `compound`, `known_moa`, and `context`:

```json
{
  "sample_id": "MY_SAMPLE",
  "compound": {"inchikey": "YOUR_COMPLETE_INCHIKEY"},
  "known_moa": [],
  "context": {"cell_line": "U2OS", "dose": null, "treatment_duration": null}
}
```

For Observation, add treatment/control image entries, channel/site/well metadata
and the explicitly prepared CP CSV/measurement metadata where available. Image
paths resolve relative to the input JSON. Use PNG/JPEG/WEBP source views supported
by the existing input loader, not raw TIFF paths. Prepare display views from your
local images without silently changing their imaging or registration semantics.
No image/CP dataset or dataset-specific download credential is included here.

Run each stage separately with the commands in the root README. Read a generated
handoff preflight error and supply a reviewed hash-bound revision when needed;
do not bypass evidence checks simply to force a caption. Use a fresh output
folder after a failed generation. Completed runs can be reused; incomplete paid
or compute-consuming attempts are not silently submitted again.

## 4. Accounting and model-specific options

Local rates are zero in the example; the USD ledger does not price H200 time.
Token usage, request counts, tool receipts and artifact seals remain recorded.
`max_input_tokens`, `max_output_tokens`, turn limits and tool limits still apply.
The example assumes a server context allowing the configured input and output
budgets together. Tune them to the actual checkpoint, image resolution and number
of images. `reasoning_effort` is not forwarded to local models. For a model that
supports it, configure `local_extra_body`, for example checkpoint-documented
`chat_template_kwargs`; these settings are intentionally not guessed here.
